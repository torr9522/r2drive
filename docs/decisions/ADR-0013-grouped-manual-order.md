# ADR-0013：按目录、分类和类型保存手动顺序

- 状态：已接受（开发候选，待正式发布）
- 日期：2026-10-30

## 问题

名称或更新时间排序无法表达用户的固定排列；顺序还必须在多级目录、网盘和图床之间隔离，并保持“文件夹在上、文件在下”。仅调整 DOM 或 localStorage 不能跨浏览器、重启和登录保存，也无法处理并发目录变化。

## 决策

`folders` 和 `files` 各增加非空整数 `sort_order`。有效排序域分别是：

- 目录：`user_id + folder_category + parent_id`。
- 文件：`user_id + file_category + folder_id`。

两张表天然形成文件夹组和文件组，前端不得混排。新增项目取本组 `MAX(sort_order)+1`；删除和移出后压紧源组；移入后追加目标同类型组末尾。重命名不改顺序。

排序 API 必须提交当前域的完整 ID 集合。服务端在 `BEGIN IMMEDIATE` 中重新读取兄弟集合，只有集合完全相等才按请求顺序写入连续整数，否则返回 409，要求客户端刷新。搜索结果不是完整集合，因此前端禁用排序。

旧库迁移按 v1.8.3 的原显示规则初始化：目录按名称稳定排序，文件按 `updated_at DESC, id`。迁移只补列和索引，不改 ID、Token、父目录或实体路径。

## 取舍

完整集合写入是 O(n)，但私人网盘目录规模有限，语义清楚且容易恢复；接口上限为 5000 项。稀疏键能减少更新，但需要重平衡和更复杂的并发规则，本阶段不采用。

## 约束

- 后续排序模式不得覆盖手动顺序；若增加名称/时间视图，必须把“展示排序”和“持久手动排序”分开。
- 拖拽与按钮排序必须串行，等待前一次保存和局部列表刷新后再计算下一步。
- 迁移和删除、上传、移动都必须覆盖排序回归。
