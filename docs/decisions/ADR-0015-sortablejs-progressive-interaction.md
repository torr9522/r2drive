# ADR-0015：桌面使用 SortableJS，移动端使用显式顺序按钮

- 状态：已接受（开发候选，待正式发布）
- 日期：2026-10-30

## 研究

Nextcloud 和 Seafile 的成熟交互共同采用行级操作、多选工具栏和带面包屑的目标目录选择器。Cloudreve 的权限与资源边界可供参考，但其 GPL 代码未复制。SortableJS `1.15.7` 为 MIT，可在原生 JavaScript 中提供手柄、动画和动态 DOM 支持。

## 决策

- 本地固定托管 SortableJS `1.15.7`，不使用运行时 CDN；保留上游 LICENSE。
- SHA256：`bf4241bc73fef7f11c59a283a69fe8051cdd31c6d8ff5a2b9ba219e7831fcf76`。
- 桌面仅拖拽 `.drag-handle`，文件夹和文件使用两个独立 Sortable 容器，不允许跨组拖动。
- 920px 以下隐藏拖拽手柄，使用上移/下移按钮，避免长按拖动抢占页面滚动。
- 搜索结果中禁用排序，因为它不是完整兄弟集合。
- 排序完成只局部替换对应列表，不重建 `.shell`，不影响上传队列、焦点和滚动状态。
- 网盘和图床共用目标目录选择器、冲突策略和批量结果反馈。

## 取舍

引入一个约 45 KiB 的第三方脚本，换取经过广泛使用的指针拖排和自动动画；不引入构建链或前端框架。移动端按钮操作步数更多，但滚动行为更可靠且可测试。

## 验证要求

桌面必须覆盖两组拖排和快速连续排序；移动端覆盖 375/390/430px 的上移、下移、选择器、取消和滚动。任何升级 SortableJS 的提交都要重新核对许可证、哈希和这些回归。
