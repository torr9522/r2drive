# ADR-0014：目录移动采用事务化逻辑关联变更

- 状态：已接受（开发候选，待正式发布）
- 日期：2026-10-30

## 问题

文件和目录需要跨多级目录单项或批量移动，同时保留文件 ID、文件夹 ID、分享 Token、统计、限额和实体内容。移动还必须阻止分类越权、伪造 ID、目录循环、父子重复选择和同名静默覆盖。

## 已确认的存储事实

实体位于 `data/storage/<user-id>/<file-id>-<safe-name>`，物理路径不包含逻辑目录层级。业务重命名也不改 `storage_path`。因此跨目录移动无需文件系统 rename；物理搬运反而会增加数据库与磁盘不一致风险。

## 决策

通用 `POST /api/items/move` 在一个 `BEGIN IMMEDIATE` 事务中：

1. 验证用户、分类、目标目录和请求结构。
2. 按 `id + user_id + category` 重新加载源项目。
3. 若父目录与其后代同时选择，后代标记 `covered_by_parent`，只移动祖先。
4. 拒绝把目录移到自身或后代，结果原因是 `cycle`。
5. 按 `cancel`、`skip` 或 `rename` 处理同类型同名冲突；绝不覆盖或合并目录。
6. 仅更新 `parent_id`/`folder_id`、必要的新显示名、`sort_order` 和 `updated_at`。
7. 项目追加到目标对应类型组末尾，并压紧所有源组。

批量结果返回 `moved`、`skipped`、`failed`。可归因到单项的缺失、循环和父子归一化使用结果数组；请求无效、目标无效和 `cancel` 冲突使用 HTTP 错误并回滚事务。

## 结果

移动不会改变实体、ID、Token、下载统计或限额。文件夹分享内容由当前后代关系动态决定：移出分享树后不再可见，移入后进入该树的访问范围；独立分享 Token 本身保持不变。

## 约束

- 网盘和图床只能在各自分类内移动，后端必须重新验证，不能信任选择器过滤。
- 如果未来实体路径改为反映逻辑层级，本 ADR 必须被新 ADR 取代，并设计可恢复的文件系统补偿事务。
- 不得把“保留整个旧数据库”当作迁移或回滚方案；升级前仍应一致性备份数据库与 storage。
