# 已知问题

`v1.9.0` 的文件管理功能已通过 Chromium、Debian 12 测试机和生产原地升级验收；下列限制仍然存在，未因正式发布而视为已解决。

## 下载统计测试时序敏感

状态：未修复。

完整下载统计在服务端响应写出后的 `finally` 中提交。隔离测试立即查询可能先于提交，出现 `downloadCount == 0`，并导致依赖前一用例状态的后续用例连锁错误。真实生产 HTTPS 验收通过有界轮询确认统计正确落库。计划修复测试等待条件，不改变统计语义。

## 未覆盖环境

- Firefox 和真实 Safari 未做浏览器验收；Playwright WebKit 专项已通过，但不能替代真实设备。
- `v1.9.1` 的移动分享入口已在 Chromium 与 WebKit 375/390/430px 验证，但没有 iPhone Safari 真机验收；特别是系统剪贴板授权提示仍需真机复核。
- Python 3.13 未做实机验收；仅通过移除 `cgi` 和依赖兼容声明处理。
- 未做高并发、压力、长时间运行和大规模故障注入。
- 手动排序每次更新完整同级同组集合，接口上限 5000 项；尚未对接近上限的超大单目录做性能测试。

## 维护限制

- `app.py` 大型单文件提高阅读成本；暂不为了形式拆分。
- 没有 CI、schema 版本表、自动备份、审计日志和孤儿文件扫描。
- 浏览器验收脚本不自动清理数据，必须使用可丢弃环境。
- 当前只支持移动，不支持复制、覆盖或同名文件夹合并。
- `deploy/Caddyfile` 含示例域名，实际部署应由 `install.sh` 生成片段。

## 安全加固机会

- `/public/` 路由没有像分享 HTML 路由一样显式限制 GET/HEAD；当前兼容契约只承诺 GET/HEAD。
- 密码哈希比较使用普通字符串比较而非 `hmac.compare_digest`。
- 没有 CSRF Token、登录限速或 CSP。现有 SameSite 和反向代理边界不能替代完整防护。

这些限制不得在发布说明中隐藏。修复后要同步本页、测试和当前基线。
